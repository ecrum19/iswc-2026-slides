06 · Finding 1

Finding 1

Algorithmic source selection rarely produced results.

Key messageAlgorithmic federation was far less reliable than manual federation.

All 25 runs, Mar 2025 – Jun 2026: Manual 47.3% non-empty / 48.5% explicit errors (260 executions) · Algorithmic 2.3% / 96.3% (1,260 executions). In April 2026, when both ran: 10 vs. 0 of 67 queries returned a non-empty result set (these runs ↗).

Elias Crum et al.Does SPARQL federation work in the real world?ISWC In-Use 2026

07 · Why algorithmic federation failed

Finding 1

Algorithmic probing exceeds endpoint usage limits.

Key messageAlgorithmic federation can exceed what live public endpoints are able to serve.

3–6 requests: 533 of 814 algorithmic executions rejected with HTTP 4xx, mostly UniProt HTTP 403: Forbidden, Sep 2025 – Jun 2026; error groups: S6. 924,299 HTTP requests were issued by one algorithmic run of query 6 before it failed (S7; results explorer ↗).

09 · Changes over time

Finding 2

Public endpoints evolve as demand grows.

Key messageEndpoint changes broke working queries; federation clients could not adapt.

68.7% of queries showed result-count variation across repeated runs, including switches between returning results and returning none (paper, Sec. 5.1). Details on each change: S9; the 14 affected queries: S10. 4 Suspected, not proven: R. Taelman, “Did AI Crawlers Kill SPARQL Federation?” (blog, 13 Apr 2026).

14 · Conclusions

Takeaways

Federation over public endpoints is not yet reliable.

  • Manual ≈ 21× more successful96% of algorithmic executions failed
  • Both approaches declinedEndpoints moved, services retired, limits tightened
  • Visible limits are a way forwardEndpoints publish them (e.g. VoRD); engines adapt

S2 · Measurement

What counts as an answer?

Non-empty result

Parseable SPARQL Results JSON with result count > 0.

Empty result

Parseable output, but zero bindings returned.

Explicit error

No usable output or an exception/error path.

Result-set size agreement is used as a proxy for consistency; the study does not claim semantic binding equality. Direct endpoint execution and the Comunica control were close (65.2% vs. 60.6% non-empty).

S13 · The running example

Query 109: transporter proteins in the liver.

# sent to sparql.uniprot.org (PREFIXes omitted)
SELECT ?rhea ?protein ?anat
WHERE {
  GRAPH <https://sparql.rhea-db.org/rhea> {
    ?rhea rh:isTransport true .
  }
  ?protein up:annotation ?ann .
  ?protein up:organism taxon:9606 .
  ?ann up:catalyticActivity ?ca .
  ?ca up:catalyzedReaction ?rhea .
  BIND(uberon:0002107 AS ?anat)
  SERVICE <https://www.bgee.org/sparql> {
    ?seq genex:isExpressedIn ?anat .
    ?seq lscr:xrefUniprot ?protein .
    ?seq orth:organism ?organism .
    ?organism obo:RO_0002162 taxon:9606 .
  }
}
Spring 2025manual · 3 runs
Fall 2025algorithmic · 4 runs
Winter 2026algorithmic · 7 runs
Spring 2026algorithmic · 10 runs
Spring 2026manual · 1 run

non-empty empty explicit error

  • Spring 2025: one manual run hit a malformed response (parse error).
  • Fall 2025: empty results (~21 requests); one run aborted after 609 requests.
  • From Nov 2025: HTTP 403 Forbidden within 2–12 requests; UniProt (and Bgee, Jun 2026) rejected the engine’s ASK probes.

Query: UniProt SPARQL example 109_uniprot_transporter_in_liver, federating UniProt and Bgee. Per-run logs: fed-survey-results ↗. The paper’s Figure 1 shows a different query, query 7 (SwissLipids), which never returned a non-empty result.
